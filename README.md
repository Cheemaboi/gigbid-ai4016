# GigBid

GigBid is a human-approved freelance copilot built for AI-4016. It ranks a local job feed, detects obvious safety problems, retrieves portfolio evidence, drafts a proposal, checks claims, and pauses for a human before producing a dry-run marketplace draft.

> This repository intentionally ships in **demo mode**. The included jobs and portfolio are synthetic, clearly labelled, and do not represent live Upwork activity.

## Why this project exists

Freelancers can lose time reading low-fit jobs and spend Connects on risky opportunities. GigBid turns a job into a short, reviewable decision record: structured requirements, risk flags, evidence, a suggested price, and an editable draft. It does not send proposals, messages, or spend Connects autonomously.

## Demo walkthrough

1. Start the FastAPI service and the React client with the commands below.
2. Open the local web URL and choose **Build a small inventory forecasting API**.
3. Select **Run safe analysis**. The run shows Scout, parallel Analyst/Risk/Fit checks, pricing, evidence verification, compliance, and an approval interrupt.
4. Review the evidence cards and editable proposal. Choose **Approve dry-run draft** to record an idempotent preview. No proposal is sent.
5. Repeat with **Urgent dashboard help - contact me on Telegram**. GigBid skips it because of scam and prompt-injection indicators.

## Local setup

Prerequisites: Python 3.11+, Node 20+, and npm. Docker is optional.

```bash
python -m pip install -e .
cd apps/web && npm install
```

Run the API in one terminal:

```bash
python -m uvicorn apps.api.main:app --reload --port 8000
```

Run the web client in a second terminal:

```bash
cd apps/web
npm run dev
```

Open `http://localhost:5173`. The API reference is available at `http://localhost:8000/docs`.

## Verification

```bash
python -m pytest -q
python evals/runners/run_demo_eval.py
cd apps/web && npm run build
```

The committed result at [`evals/results/demo_eval.json`](evals/results/demo_eval.json) is regenerated by the evaluation command. It is a three-job synthetic smoke run, not a claim about production response or hire rate.

## Architecture

```text
React reviewer UI -> FastAPI -> executable LangGraph -> typed handoffs
                                  |          |             |
                           Portfolio MCP  Marketplace MCP  Workspace MCP
                                  |
                        synthetic portfolio evidence
```

The graph is deliberately small enough to inspect in [`agent/graphs/bid_graph.py`](agent/graphs/bid_graph.py). It is an executable `StateGraph`: Scout fans out to parallel Job Analyst, Risk Assessor, and Fit Matcher nodes, joins at decision, then continues through pricing, writer, verifier, and compliance. LangGraph interrupts before the human-approval node; the separate API endpoint records the reviewer-approved dry-run preview.

| Deployment | `render.yaml` and Docker images | Render hosts the full same-origin app/API and the Portfolio MCP server; the static GitHub Pages site is only a browser fallback |

## Safety decisions

- Job text is untrusted input. The risk node detects planted off-platform/free-work/instruction patterns before a proposal is written.
- Proposal claims are split and labelled supported, partly supported, or unsupported. Claims linked to prohibited phrases are blocked.
- Every marketplace write accepts an idempotency key and remains a dry-run until a human approves it in the UI.
- No scraper, browser cookie, or browser automation is used. Live access is a future official-MCP/OAuth integration only.
- The repository contains no secrets. Copy `.env.example` to `.env` locally and replace the demo password before deployment.
